## 6. Deviations, caveats and audit trail

- **Adapters are pilot-scale.** Full-data LoRA (16,377 training videos) did not fit the deadline; every LoRA result uses 1,000 training videos, one pass, single seed.
- **Direct LoRA suppresses thinking in M1/M2.** Thinking stays enabled and unforced at inference, but the adapted models think less (M1) or not at all (M2), and under-segment. RFT (section 3) tests a fix.
- **E1 zero-shot ran on physical GPU2** (authorized 2026-11-17) with the frozen driver and settings; all other test runs used GPU0. GPU0's own E1-ZS step was intentionally blocked by a placeholder directory and appears as a failure in its issue log.
- **Encoder-decoder inference** uses the batched greedy driver for both arms; it is statistically equivalent but not token-identical to sequential decoding (55% identical raw text on 816 windows).
- **Window packing:** transcripts longer than 8,192 tokens are split into windows with 16-sentence context and stitched; multi-window videos remain much harder (section 4). No transcript is truncated.
- **Data:** deduplicated/quarantined variant (train 16,377; validation 1,446); test 1,448 videos, audited unique and disjoint from train/validation; test data was first read after the freeze.

## Appendix A. Method

**Task and output.** Input is a transcript split into numbered sentences. The model returns one JSON object `{"chapters":[{"start":<sentence index>,"title":"..."}]}`. Every system gets the same prompt (`owned-window-outline-v1`), and the output is parsed strictly.

**Windows.** At most 8,192 input tokens per window, counted with the rendered prompt under all four tokenizers, so the windows are identical for every backbone. A longer transcript is cut into consecutive windows. Each window owns a disjoint block of sentences [A,B), as large as fits, and also shows up to 16 sentences of context on each side, [L,R). The model must list L first as a processing anchor. Only starts inside each window's owned block are kept, and the blocks are concatenated in order. Stitching never merges, sorts or invents anything. Any failed window fails the video. No transcript is truncated.

**Metrics.** Sentence space, macro over every requested video; failed videos stay in the average.

- **Exact F1 (primary).** A boundary is the first sentence of every chapter after the first. Per video, predicted boundaries are matched to reference boundaries only at the identical sentence index, and F1 = 2·TP / (2·TP + FP + FN). This is macro-averaged over all requested videos. A video with no internal boundaries in either reference or prediction scores 1.
- **±2 F1.** Same as exact F1, but a predicted boundary counts if it lies within 2 sentences of an unmatched reference boundary (one-to-one, maximum matching). It forgives near misses.
- **Pk ↓.** Slide a probe of k sentences over the transcript, where k is half the mean reference chapter length. At each position, it is an error when reference and prediction disagree about whether the probe's two ends are in the same chapter. Pk is the error rate, so lower is better.
- **WindowDiff ↓.** Same probe, but it is an error whenever the number of boundaries inside the probe differs. It penalizes extra or missing boundaries that Pk can miss. Lower is better.
- **B-sim.** Boundary Similarity (segeval). An edit-distance score over the two boundary sequences in which near-miss transpositions get partial credit. Higher is better.
- **Title ROUGE-L.** Per video, all predicted titles are concatenated in order and compared with the concatenated reference titles by ROUGE-L F1 (longest common subsequence). Macro over videos.
- **Title BERTScore.** Reference and predicted chapters are paired one-to-one by sentence span (span IoU ≥ 0.5; titles are never read for pairing). Each pair's titles are scored with BERTScore F1 (RoBERTa-large, layer 17). Averaged over reference chapters, with an unmatched reference chapter counting 0.
- **Failed videos.** Videos with no usable answer: invalid or non-JSON output, a structure that breaks the contract, or generation cut off at the output budget. Any failed window fails its whole video. A failed video scores 0 on F1, B-sim and title metrics, and 1 (worst) on Pk and WindowDiff. Nothing is repaired.
- **Predicted / reference chapters.** Total predicted chapters on successful videos divided by total reference chapters. Above 1 means over-segmenting, below 1 means under-segmenting.
- **LoRA − zero-shot [95% CI].** Paired bootstrap: take the per-video exact-F1 difference between two systems on the same videos, resample videos with replacement 10,000 times (seed 20261116), and report the 2.5th–97.5th percentile. An interval that excludes 0 is shown in colour.

**Training parameters (all LoRA runs).**

- Adapter: LoRA rank 16, alpha 32, dropout 0.05, on attention q/k/v/o; base frozen; bfloat16. M1 (Qwen3.5-9B, hybrid) has full attention only in every 4th layer, so its adapter covers 8 of 32 layers (3.9 M parameters); the 24 linear-attention layers are not adapted.
- Optimizer: AdamW, LR 2e-4, cosine decay, gradient clipping 1.0.
- Batching: one window per forward pass, gradient accumulation 8 (effective batch 8 windows), gradient checkpointing.
- Schedule: one pass; warmup 10 steps (direct) or 3 (RFT); seed 393.
- Direct LoRA data: 1,000 training videos, 1,306 windows, gold chapter JSON target, with titles cut by a window edge masked out of the loss.
- Direct LoRA loss: E1/E2 decoder cross-entropy on the JSON; M1/M2 causal loss on final JSON plus turn-end only. Prompt unscored; no reasoning text written or supervised.
- RFT LoRA loss: the model's own selected sample (thought + JSON + turn end), fully supervised after the unscored prompt.
- Inference: M1/M2 vLLM, native thinking unforced, temperature 1.0, top-p 0.95, top-k 20 (M1, presence penalty 1.5) or 64 (M2), per-window seed, up to 32,768 new tokens. E1/E2 greedy, batched by length tier, up to 4,096 new tokens. ZS and LoRA share path and settings.

**RFT recipe (`rft_self_samples_v1`).** (1) Sample each training window 4 times from the base model (seeds 1001-4004, the zero-shot sampling settings). (2) Score each finished, strictly valid sample by exact F1 of its starts inside the owned block, anchor excluded, against gold. (3) Keep the best sample if F1 ≥ 0.5. (4) One-pass LoRA on prompt → own thought → own JSON → turn end. v1: 300 windows via the GPU1 services. v2: all 1,306 pilot windows (the other 1,006 sampled locally with identical settings); same recipe and hyperparameters.
