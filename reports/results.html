LLM Video Chaptering Results

YouTube video chaptering (retkowski/ytseg) with four backbones, each zero-shot and LoRA-adapted. Exact boundary macro F1 is primary; a video whose output fails strict parsing scores 0.

Complete: eight test configurations scored (04:14 UTC) · RFT v2 dev follow-up scored (06:31 UTC)

Summary

  • Best test result: E2 (T5Gemma 2B-2B) with LoRA, exact F1 0.500 (±2-sentence F1 0.679, Pk 0.229, WindowDiff 0.251). It beats E1 (T5Gemma 9B-2B) with LoRA, 0.484, by +0.017 [+0.008, +0.026], and the best decoder-only setup, M2 (Gemma 4 12B) zero-shot at 0.451, by +0.049 [+0.039, +0.059]. Both comparisons are post-hoc, paired by video. The smaller encoder-decoder wins.
  • LoRA turns the encoder-decoders from unusable into the best systems. E1 gains +0.481 [+0.465, +0.497]: zero-shot E1 produces strictly valid output for only 13 of 1,448 videos (0.003). E2 gains +0.352 [+0.335, +0.368]: zero-shot E2 fails on 477 videos. Most of the zero-shot gap is output format. Under the lenient reading, zero-shot E1 recovers to 0.237 and E2 to 0.157, still far below LoRA.
  • LoRA hurts the decoder-only models. M1 (Qwen3.5-9B) drops from 0.403 to 0.365 (−0.038 [−0.049, −0.026]); M2 drops from 0.451 to 0.344 (−0.108 [−0.119, −0.096]). Zero-shot, M2 beats M1 by +0.048 [+0.039, +0.057].
  • Why M1 and M2 get worse: answer-only LoRA teaches them to stop thinking. Median reasoning per window drops from 7,192 to 3,328 tokens for M1 and from 4,907 to 0 for M2 (dev). The adapted models under-segment, with predicted/reference chapters 0.97 and 0.81 against 1.25 and 1.48 zero-shot. M1 LoRA also fails on 116 test videos (65 under the lenient reading).
  • Rejection-sampling fine-tuning (RFT) repairs the damage, and with more data M1 starts to gain. RFT trains M1/M2 on their own best sampled reasoning plus answer. v1 (300 windows) brought thinking back and returned dev F1 to zero-shot level. v2 uses the same recipe on all 1,306 windows of the direct-LoRA training videos (599 / 573 kept). M1 RFT v2 reaches 0.440 on dev, the best M1 result: +0.031 [+0.010, +0.052] over RFT v1 and +0.019 [−0.003, +0.041] over zero-shot (a trend, not yet significant), against −0.042 for direct LoRA. M2 RFT v2 stays at zero-shot level, 0.464 vs 0.459 (+0.005 [−0.010, +0.020]); more data did not help M2. RFT is dev-only and was never run on test.
  • Dev predicted test well. All four LoRA effects keep their sign and roughly their size from dev to test: E1 +0.508 → +0.481, E2 +0.321 → +0.352, M1 −0.042 → −0.038, M2 −0.114 → −0.108.

Method

Task and output

Input is a YouTube transcript split into numbered sentences. The model returns one JSON object, {"chapters":[{"start":<sentence index>,"title":"…"}]}, listing where each chapter starts and a short title. Every system gets the same prompt (owned-window-outline-v1). The output is parsed strictly: anything other than exactly that JSON object fails.

Windows: how long transcripts are handled

Every model gets at most 8,192 input tokens, counted with the actual rendered prompt under all four tokenizers so that the windows are identical for every backbone. A transcript that fits is one window. A longer one is cut into consecutive windows. Each window owns a disjoint block of sentences [A,B), as large as fits, and also shows up to 16 sentences of context on each side, [L,R). The model must list sentence L first; it is a processing anchor, not a claimed boundary. After all windows are generated, only chapter starts inside each window's owned block are kept, and the blocks are concatenated in order. Because the blocks tile the transcript exactly, stitching never merges, sorts or invents anything. If any window of a video fails, the whole video fails. No transcript is truncated.

Metrics

All boundary metrics are computed in sentence space against the reference chapters, macro-averaged over every requested video. Failed videos stay in the average.

Exact F1 (primary)
A boundary is the first sentence of every chapter after the first. Per video, predicted boundaries are matched to reference boundaries only at the identical sentence index, and F1 = 2·TP / (2·TP + FP + FN). This is macro-averaged over all requested videos. A video with no internal boundaries in either reference or prediction scores 1.
±2 F1
Same as exact F1, but a predicted boundary counts if it lies within 2 sentences of an unmatched reference boundary (one-to-one, maximum matching). It forgives near misses.
Pk ↓
Slide a probe of k sentences over the transcript, where k is half the mean reference chapter length. At each position, it is an error when reference and prediction disagree about whether the probe's two ends are in the same chapter. Pk is the error rate, so lower is better.
WindowDiff ↓
Same probe, but it is an error whenever the number of boundaries inside the probe differs. It penalizes extra or missing boundaries that Pk can miss. Lower is better.
B-sim
Boundary Similarity (segeval). An edit-distance score over the two boundary sequences in which near-miss transpositions get partial credit. Higher is better.
Title ROUGE-L
Per video, all predicted titles are concatenated in order and compared with the concatenated reference titles by ROUGE-L F1 (longest common subsequence). Macro over videos.
Title BERTScore
Reference and predicted chapters are paired one-to-one by sentence span (span IoU ≥ 0.5; titles are never read for pairing). Each pair's titles are scored with BERTScore F1 (RoBERTa-large, layer 17). Averaged over reference chapters, with an unmatched reference chapter counting 0.
Failed videos
Videos with no usable answer: invalid or non-JSON output, a structure that breaks the contract, or generation cut off at the output budget. Any failed window fails its whole video. A failed video scores 0 on F1, B-sim and title metrics, and 1 (worst) on Pk and WindowDiff. Nothing is repaired.
Predicted / reference chapters
Total predicted chapters on successful videos divided by total reference chapters. Above 1 means over-segmenting, below 1 means under-segmenting.
LoRA − zero-shot [95% CI]
Paired bootstrap: take the per-video exact-F1 difference between two systems on the same videos, resample videos with replacement 10,000 times (seed 20261116), and report the 2.5th–97.5th percentile. An interval that excludes 0 is shown in colour.

Training parameters

Shared settings for every LoRA run (direct and RFT)
AdapterLoRA rank 16, alpha 32, dropout 0.05, on attention q/k/v/o projections; base weights frozen, bfloat16. M1 (Qwen3.5-9B) is a hybrid model, and only every 4th layer is full attention, so its adapter covers 8 of 32 layers (3.9 M parameters). The 24 linear-attention layers have no q/k/v/o projections and are not adapted.
OptimizerAdamW, learning rate 2e-4, cosine decay, gradient clipping 1.0
Batchingone window per forward pass, gradient accumulation 8 (effective batch 8 windows), gradient checkpointing
Scheduleexactly one pass over the prepared windows; warmup 10 steps (direct) or 3 steps (RFT, far fewer steps); seed 393
Direct LoRA data1,000 training videos, 1,306 windows (seeded sample of the 16,377-video deduplicated train split). The target is the gold chapter JSON for the window, with titles cut by a window edge masked out of the loss.
Direct LoRA lossE1/E2: decoder cross-entropy on the JSON target. M1/M2: causal LM loss on the final JSON plus the native turn-end token only. The prompt is unscored, and no reasoning text is written, supervised or invented.
RFT LoRA lossM1/M2: the model's own selected sample, thought plus final JSON plus turn end, supervised in full after the exact generation prompt (unscored). See the RFT section.
InferenceM1/M2: vLLM, native thinking on and unforced, temperature 1.0 / top-p 0.95 / top-k 20 (M1, presence penalty 1.5) or 64 (M2), per-window seed, up to 32,768 new tokens. E1/E2: greedy decoding, batched by length tier, up to 4,096 new tokens. Zero-shot and LoRA use the same path and settings.

Rejection-sampling fine-tuning (RFT) for M1 and M2

Direct LoRA trains M1/M2 only on the final JSON answer, and that teaches them to skip reasoning. RFT, the simplest reinforcement-style recipe, is expert iteration with a binary reward: the model generates, a reward picks its best attempts, and LoRA trains on those attempts, reasoning included. All text is the model's own; nothing is written or edited by us. RFT is a dev-only follow-up after the freeze, not one of the eight test configurations.

  1. Sample. The base model answers each training window 4 times (seeds 1001/2002/3003/4004, temperature 1.0, the same sampling as zero-shot inference, native thinking on, up to 32,768 new tokens).
  2. Score. Each finished, strictly valid sample gets the exact F1 of its chapter starts inside the window's owned block [A,B) (anchor excluded) against the gold starts in that block.
  3. Select. Keep the best sample per window if its F1 is at least 0.5; otherwise drop the window. Gold text never enters the training sequence, only the choice of sample.
  4. Train. One-pass LoRA (shared settings above, warmup 3) on prompt → own thought → own JSON → turn end. Loss covers everything after the prompt.

v1 sampled 300 windows (233 videos) through the GPU1 vLLM services. v2 keeps the recipe and every setting, and adds the other 1,006 windows of the same 1,000 training videos the direct LoRA used (local vLLM on GPU0/GPU2, same sampling settings and seed scheme). Selection then runs over all 1,306 windows, so v2 differs from v1 only in data scale, and RFT v2 versus direct LoRA compares training signals on identical videos.

  • E1 zero-shot fails on 1,435 of 1,448 videos. In 1,175 of them the JSON is valid but wrapped in a Markdown fence, a habit of the instruction-tuned model. 129 hit the 4,096-token cap, 127 of them by listing a new "chapter" almost every sentence. 83 have broken JSON, and 46 add other text.
  • E2 zero-shot fails on 477 videos, mostly by talking instead of answering: 261 cases of extra text, including 113 with no JSON at all (summaries, or chat replies such as "You are correct. I apologize…"). There are also 93 fence or period wrappers and 51 cut-offs, 41 of them echoing the transcript.
  • LoRA fixes the format for the encoder-decoders. Failed videos drop to 27 (E1) and 4 (E2). E1's remaining failures are mostly titles that quote something without escaping the quotes (13 of 27, e.g. "Victor Frankl's "Man Search for Meaning"").
  • M1/M2 zero-shot almost never fail (4 and 1 videos). Their native thinking ends in clean JSON.
  • Answer-only LoRA makes M1/M2 sloppier.
    • M1 LoRA fails on 116 videos. 58 add Markdown fences that zero-shot never produced, 23 have invalid starts, and 12 never finish thinking.
    • M2 LoRA fails on 46, mainly from invalid starts (27) and broken JSON (18, mostly unescaped quotes in titles).
  • Chapter count.
    • Zero-shot M1/M2 over-segment: pred/gold 1.25 and 1.48. Most of that comes from long videos (table above).
    • Their LoRA versions predict fewer chapters (1.08 and 0.85). M2 LoRA under-segments 54% of videos.
    • The encoder-decoder LoRAs are closest to gold: 0.97 and 0.97, with 53% of E2 videos within ±1 chapter, and the highest rank correlation with gold counts.
    • E2 zero-shot's counts barely track gold (ρ 0.16). It gives one chapter per sentence in 284 videos and a single chapter in 177.
  • Long videos are the main remaining weakness. Every configuration loses F1 sharply from 1 window to 3+ windows (table above), and M1/M2 zero-shot nearly double the chapter count there.

Caveats and audit trail

  • Adapters are pilot-scale. Every LoRA result uses 1,000 training videos (1,306 windows), one pass, one seed. Full-data training (16,377 videos) did not fit the deadline, so the LoRA numbers are a lower bound on what adaptation can do. M1's adapter is also narrow: Qwen3.5-9B is a hybrid model, and q/k/v/o LoRA reaches only its 8 full-attention layers (3.9 M parameters, against 19–32 M for the other backbones).
  • Thinking stays enabled for M1/M2 at inference in both arms; nothing forces or strips it. Direct LoRA supervises only the final JSON answer with verified masks. No reasoning text was invented: RFT trains only on the model's own unedited samples.
  • E1 zero-shot ran on physical GPU2 (authorized on 2026-11-17) with the frozen driver, settings and hashes, taking 5.7 h of generation. All other test runs used GPU0. GPU0's own E1-ZS step was blocked on purpose by a placeholder directory, so it shows up as a logged failure below.
  • E1 zero-shot failure modes (test): 1,306 invalid and 129 truncated at the 4,096-token output cap, with 13 valid. Truncation is reported, not repaired.
  • Encoder-decoder inference uses the batched greedy driver for both arms. It is statistically equivalent to sequential decoding but not token-identical (55% identical raw text on 816 dev windows).
  • Cross-backbone comparisons (E2 vs E1, E2/E1 vs M2, M2 vs M1) are post-hoc. They use the same paired bootstrap (10,000 resamples, seed 20261116); the file is artifacts/heldout-test-v1/posthoc/cross_backbone_bootstrap.json. The frozen primary comparisons are the four within-backbone LoRA − zero-shot effects.
  • Long transcripts are packed into 8,192-token windows with 16 sentences of context, then stitched. Nothing is truncated on input. Multi-window videos score far lower: zero-shot M1/M2 on full validation reach 0.16–0.23 there, against 0.44–0.50 for single-window videos.
  • Data: deduplicated/quarantined variant (train 16,377, validation 1,446). The test split has 1,448 videos, audited as unique and disjoint from train/validation. Test data was first read after the configurations were frozen. RFT is a dev-only follow-up after the freeze, not one of the eight test configurations.
